## Project Stage

**presupuesto_personal** is an early-stage personal finance platform under Spec-Driven Development (SDD). No application stack or source code has been implemented yet. The project captures requirements via an Excel workbook that drives architecture and task decisions.

## Reference Source

The authoritative domain model lives in:
- `example/Finanzas Personales 2026.xlsx` — 17 sheets documenting monthly income/expense tracking, user workflows, and financial categories.

**Before proposing architecture or implementation, examine this workbook.** It contains the actual user mental model, not abstract requirements.

## SDD Workflow

This repository uses Spec-Driven Development (SDD) with persistent memory via Engram. The workflow phases are:

1. **Explore** — Investigate ideas, examine the workbook, understand current architecture (if any).
2. **Propose** — Formalize intent, scope, and approach into a proposal document.
3. **Spec** — Write formal requirements and scenarios (delta specs).
4. **Design** — Define technical architecture and approach.
5. **Tasks** — Break down into actionable, ordered work items.
6. **Apply** — Implement code changes following existing patterns.
7. **Verify** — Validate that implementation matches specs, design, and tasks.
8. **Archive** — Close the change, merge delta specs into main specs.

Use the `/sdd-*` skills to guide each phase. Memory persists across sessions, so prior decisions and discoveries remain available.

## SDD Artifacts

The `.atl/` directory (gitignored) holds SDD working documents:
- `spec/main/` — Baseline specs and architecture
- `spec/delta/` — Active change proposals, specs, designs, tasks
- `archive/` — Completed changes with final reports

These files are generated by SDD phases and should not be edited manually.

## Development Approach

- **Architecture**: No stack chosen yet. Architecture decisions should emerge from requirements exploration, not assumed.
- **Testing**: No test framework selected. Testing approach will be defined as part of design/task phases.
- **Memory**: Use Engram for decisions, discoveries, and conventions. Call `mem_save` proactively after decisions are made.
